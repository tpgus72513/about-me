# About Me — 자기소개 페이지

언더독 웹 기초 챌린지로 만드는 권세현의 자기소개 페이지입니다.
HTML과 CSS로 페이지를 구성하고, GitHub Pages로 배포하는 과정을 학습합니다.

## 배포 페이지

- **[로즈 머스크 — 제출용 기본 페이지](https://tpgus72513.github.io/about-me/)**
- [클리어 네이비 — 비교 시안](https://tpgus72513.github.io/about-me/variants/clear-navy/index.html)
- [Velog 학습 기록](https://velog.io/@tpgus72513/posts)

GitHub Pages에서 `main` 브랜치의 최상위 폴더(`/`)를 배포하며 HTTPS를 사용합니다. 해당 브랜치에 변경 사항을 push하면 배포 작업이 다시 실행됩니다.

## 프로젝트 목적

- HTML로 제목, 문단, 이미지, 링크 등 페이지의 구조를 작성합니다.
- CSS로 색상, 글자, 여백과 이미지 스타일을 적용합니다.
- Flexbox와 반응형 CSS로 다양한 화면 크기에 맞는 배치를 만듭니다.
- 단계별 작업을 Git 커밋으로 남기고, 배운 내용과 시행착오를 Velog에 기록합니다.
- 작성한 코드와 적용한 개념을 자신의 말로 설명할 수 있도록 학습합니다.

## 페이지에 담을 내용

- 이름과 간단한 자기소개
- 관심 분야와 학습 목표
- 대표 프로젝트와 담당 역할
- GitHub 및 Velog 링크

## Day 5 — 배포와 최종 점검

- 배포 방식: Settings → Pages → Deploy from a branch → `main` / `(root)`
- 정적 파일 배포: `.nojekyll`을 추가해 HTML·CSS·이미지를 그대로 제공합니다.
- 공개 주소 확인: 두 페이지와 CSS·이미지·아이콘이 모두 HTTP 200으로 응답했습니다.
- 화면 확인: 두 시안 모두 320·390·1440px에서 가로 넘침과 이미지 누락이 없었습니다.
- HTML 확인: 중복 id, 누락된 메뉴 대상, 빈 링크 문구가 없었습니다.
- 학습 기록 연결: 두 시안에 실제 Velog 프로필 링크를 추가했습니다.

GitHub Pages는 저장소의 HTML·CSS·이미지를 웹 주소로 제공하는 정적 웹 호스팅입니다. 공개 주소는 로컬 미리보기 서버를 켜 두지 않아도 사용할 수 있습니다.

배포 설정은 [GitHub 공식 문서](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 참고했습니다.

## Day 4 — Flexbox와 반응형 구성

- 메뉴: 부모 `ul`에 `display: flex`, `justify-content: center`, `flex-wrap: wrap`을 적용해 가운데 정렬하고 공간이 부족하면 줄을 바꿉니다.
- 프로젝트: `.project-list`가 세 개의 `article`을 배치합니다. 768px 미만에서는 세로로, 768px 이상에서는 가로로 놓고 너비에 따라 줄을 바꿉니다.
- 프로젝트 너비: `flex: 1 1 280px`로 기준 너비를 정하고 남는 공간을 나눠 씁니다. 넓은 화면에서는 세 개, 중간 화면에서는 두 개와 한 개가 두 줄로 표시됩니다.
- 링크 정렬: 각 프로젝트도 세로 Flexbox로 구성하고 링크 문단에 `margin-top: auto`를 적용해 같은 줄의 링크를 아래쪽에 맞춥니다.
- 모바일: 작은 제목·여백과 3:2 이미지 비율을 사용합니다. 768px 이상에서는 제목과 여백을 키우고 이미지를 3:1로 표시합니다.
- 푸터: 작은 화면에서는 세로로, 넓은 화면에서는 가로로 배치합니다.

작은 화면의 스타일을 먼저 작성하고 `@media (min-width: 768px)`에서 넓은 화면의 규칙을 추가하는 방식입니다. 768px은 이번 페이지의 배치를 조정하기 위해 선택한 기준이며, 특정 기기를 자동으로 식별하는 값은 아닙니다.
클리어 네이비는 Day 3 비교 자료로 유지합니다.

브라우저에서는 320·390·767·768·900·1440px 너비의 배치와 이미지 로딩을 확인했습니다. 모든 확인 너비에서 가로 넘침이 없었고, 키보드 포커스와 메뉴 이동도 동작했습니다.

## 디자인 방향

현대적이고 차분한 화면에 은은한 여성스러움을 더한 ‘로즈 머스크’ 분위기입니다.
따뜻한 아이보리 바탕에 로즈·플럼 계열의 글자와 얇은 구분선을 사용했습니다.

| 역할 | 색상 |
| --- | --- |
| 배경 | `#F8F4F1` |
| 밝은 영역 | `#FFFDFB` |
| 본문 | `#3D3038` |
| 보조 글자 | `#74636D` |
| 강조·링크 | `#875668` |
| 구분선 | `#E4D5DA` |

제목은 Gowun Batang, 본문은 Noto Sans KR을 사용합니다.
웹 글꼴을 불러오지 못하면 컴퓨터의 바탕체와 고딕체로 표시됩니다.
장식 이미지는 OpenAI의 이미지 생성 도구로 만들었으며 실제 인물이나 제품을 나타내지 않습니다.

## 제출 테마와 비교 시안

**이번 동아리 과제의 제출 테마는 로즈 머스크입니다.** 저장소 최상위의 `index.html`이 기본 페이지이며, Day 4와 Day 5 작업도 이 버전을 기준으로 진행합니다.

| 구분 | 로즈 머스크 — 제출용 기본 페이지 | 클리어 네이비 — 비교 시안 |
| --- | --- | --- |
| 파일 | [index.html](./index.html) | [variants/clear-navy/index.html](./variants/clear-navy/index.html) |
| 색상 | 아이보리·로즈·플럼 | 화이트·블루그레이·네이비 |
| 제목과 정렬 | 명조체, 상단 가운데 정렬 | 고딕체, 왼쪽 정렬 |
| 이미지 | 로즈빛 유리와 흰 꽃 | 흰 건축물과 푸른 하늘 |
| 의도 | 최근 좋아하는 부드럽고 고급스러운 분위기 표현 | 공식적이고 정돈된 프로필 분위기 비교 |

평소 입는 옷의 스타일은 클리어 네이비에 가깝지만, 요즘 좋아하는 분위기는 로즈 머스크에 더 가깝습니다. 이번 과제에서는 현재 표현하고 싶은 취향을 담기 위해 로즈 머스크를 선택했습니다.

클리어 네이비는 같은 자기소개 내용을 색상·글꼴·정렬·이미지에 따라 어떻게 다르게 표현할 수 있는지 살펴본 **Day 3 비교 자료**로 보관합니다. 향후 취업용 포트폴리오를 구성할 때 참고할 수 있으며, [별도 설명](./variants/clear-navy/README.md)에 CSS 비교 포인트를 정리했습니다.

두 시안의 코드와 이미지는 AI의 도움으로 준비했습니다. 과제 학습 과정에서는 적용한 속성을 직접 확인하고 자신의 말로 설명하는 것을 목표로 합니다.

## 실행 방법

별도의 설치나 빌드 없이 아래 방법으로 확인할 수 있습니다.

1. 저장소를 컴퓨터에 내려받습니다.
2. `index.html`을 웹 브라우저로 엽니다.
3. HTML이나 CSS를 수정했다면 파일을 저장하고 브라우저를 새로고침합니다.

`index.html`과 `style.css`를 같은 폴더에 두고 `assets` 폴더도 함께 유지합니다.
페이지의 HTML·CSS·이미지는 로컬에서 열 수 있으며, Google Fonts 웹 글꼴을 불러올 때는 인터넷 연결이 필요합니다.

클리어 네이비는 `variants/clear-navy/index.html`을 열거나 기본 페이지 하단의 비교 시안 링크로 확인할 수 있습니다. 각 페이지 하단의 링크로 두 스타일을 오갈 수 있습니다.
